PORTSAID TRADING

==================================================
PROJECT OBJECTIVE
==================================================

Create a professional B2B website that allows PORTSAID TRADING to:

- Display and organize products.
- Present detailed product specifications, images, documents, certifications, and packaging information.
- Allow visitors to search, filter, and compare products.
- Receive requests for quotations instead of requiring immediate online payment.
- Allow customers to create and manage their own accounts.
- Allow authorized employees to add and manage customers manually.
- Interact with website visitors through a multilingual chat experience powered by the company’s existing n8n automation and AI-chat workflows.
- Pass website, visitor, product, and quotation context securely to the existing n8n workflows.
- Connect customers to the company’s existing Meta-connected WhatsApp number.
- Analyze visitor journeys, behavior, searches, and product interests.
- Convert anonymous visitors into identified leads and registered customers after they voluntarily provide identifying information.
- Connect securely with the existing Bizim Hesap ERP/accounting system.
- Connect securely with the existing company email and Telegram systems.
- Operate as an installable mobile Progressive Web App.
- Be simple enough for non-technical employees to manage without editing code.

==================================================
SYSTEM RESPONSIBILITIES
==================================================

Do not duplicate functionality unnecessarily.

Use the following initial responsibility model, subject to verification during the discovery phase:

1. WEBSITE APPLICATION

The website should manage:

- Public product-catalog presentation.
- Multilingual content.
- Customer registration and authentication.
- Customer portal.
- Quotation requests.
- Website consent records.
- Anonymous visitor sessions.
- First-party website analytics.
- Product-interest events.
- PWA functionality.
- Website administration.

2. EXISTING N8N INSTANCE

The existing n8n instance should manage:

- Chatbot and AI workflows.
- Workflow automation.
- Secure routing of data between systems.
- Notifications.
- Lead-processing workflows.
- Human-handover workflows.
- Meta WhatsApp workflow integration.
- Telegram workflow integration.
- Email workflow integration.
- Approved Bizim Hesap synchronization workflows.

Do not use n8n as the website’s primary transactional database unless the current architecture explicitly requires this and the decision is approved.

3. BIZIM HESAP

Treat Bizim Hesap as the source of truth only for the entities confirmed by its available API and the company’s current configuration.

Possible supported entities include:

- Products.
- Warehouses.
- Inventory quantities.
- Orders.
- Invoices.

Do not assume that Bizim Hesap supports customer, quotation, payment, or bidirectional synchronization endpoints until the actual API documentation and account permissions are inspected.

Create a field-by-field integration map before implementation.

4. META WHATSAPP CLOUD API

Use the existing Meta-connected company number and existing webhook architecture.

Do not:

- Register a replacement number.
- Create a conflicting webhook.
- Expose Meta credentials.
- Interrupt current conversations.
- Replace existing approved message templates.
- Use unofficial WhatsApp automation.

5. COMPANY EMAIL AND TELEGRAM

Use the existing approved accounts, APIs, bots, credentials, templates, and workflows.

Do not create replacement accounts unless explicitly requested.
